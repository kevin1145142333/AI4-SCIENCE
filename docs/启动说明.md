# AI4 Science 启动说明（Windows）

> 本文件记录 2026-10-15 修复后的启动方式。目录：`C:\Users\26733\Documents\ChatGPT\AI4 Science`

## 零、现在不需要你手动启动（2026-10-16 起）

已经做成"开机就绪"，你只用打开网页：

| 东西 | 位置 | 作用 |
| --- | --- | --- |
| 计划任务 `AI4 Science Web` | Windows 任务计划程序 | 登录时启动服务（只检查这一次，不再定时弹出窗口） |
| 桌面图标 `AI4 Science 网页` | 桌面 | 直接打开 http://localhost:8501 |
| 桌面图标 `AI4 Science 启动` | 桌面 | 万无一失版：先确认服务在跑（不在跑就拉起来），再打开网页 |
| 看护日志 | `logs\watchdog.log` | 记录每次"服务掉线 → 自动重启"的时间 |

**手动检查**：平时服务若打不开，双击桌面的"AI4 Science 启动"即可（它会在需要时把服务拉起来）；
也可以手动触发计划任务：

```powershell
schtasks /run /tn "AI4 Science Web"
```

不想让它自动启动时，在"任务计划程序"里禁用 `AI4 Science Web` 即可，或执行：

```powershell
schtasks /change /tn "AI4 Science Web" /disable   # 关闭自启
schtasks /change /tn "AI4 Science Web" /enable    # 恢复自启
```

下面的 `.bat` 脚本仍然可用，但已经只是备用手段。

## 一、最快路径

双击 `start_web.bat`（或下面的命令行方式），等服务就绪后会自动打开
http://localhost:8501 。想要"关掉 VS Code 也还在跑"，用 `start_web_bg.bat`。

| 脚本 | 作用 | 说明 |
| --- | --- | --- |
| `start_web.bat` | Web 界面（前台） | 日志直接显示在窗口里，按 Ctrl+C 停止 |
| `start_web_bg.bat` | Web 界面（后台） | 关掉终端 / VS Code 后服务仍在跑，用 `stop_web.bat` 停止 |
| `stop_web.bat` | 停止 Web 服务 | 关闭占用 8501 端口的服务进程 |
| `start_api.bat` | REST API | http://localhost:8000/docs |
| `start_cli.bat` | 命令行模式 | 例如 `start_cli.bat --query "钙钛矿稳定性" --trl` |

## 二、在 VS Code 里启动

在 VS Code 的终端里必须带 `.\` 前缀（PowerShell 不会自动在当前目录找可执行文件）：

```powershell
.\start_web.bat          # 推荐：日志可见
.\start_web_bg.bat       # 后台常驻
.\stop_web.bat           # 停止
```

如果终端是 cmd，则直接用 `start_web.bat`。

**注意**：`start_web.bat` 是前台进程，终端窗口（或 VS Code）关掉服务就停了——
这正是"之前能访问、过一会儿又打不开"的常见原因。需要长期可访问请用 `start_web_bg.bat`。

## 三、常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 浏览器打不开 localhost:8501 | 服务没在运行 | 先跑 `start_web.bat` 看日志；或 `stop_web.bat` 后再 `start_web_bg.bat` |
| 报告里"总计 0 篇" | 服务所在进程没有外网权限 | 在普通（非沙箱）终端里用本目录脚本启动服务，不要用受限环境托管 |
| 端口被占用 | 8501 已被别的程序占用 | 启动脚本会直接提示；也可改 `.env` 的 `WEB_PORT` |
| 引用数/总被引为 0 | Semantic Scholar 未配 key，被限流跳过 | 在 `.env` 填 `SEMANTIC_SCHOLAR_API_KEY` |
| 提示找不到虚拟环境 | `venv` 缺失或损坏 | `py -3 -m venv venv` 然后 `venv\Scripts\python.exe -m pip install -r requirements.txt` |

## 四、2026-10-15 的修复内容

1. **启动脚本（`start_web.bat` / `start_api.bat` / `start_cli.bat`）重写**
   - 原文件是 UTF-8 中文 + LF 换行，而 Windows 控制台默认 GBK 代码页：
     脚本被逐行当成乱码命令执行（`'…' is not recognized as an internal or external command`），
     并且 `call venv\Scripts\activate.bat` 被跳过，最后用系统 Python 跑 `main.py`
     报 `ModuleNotFoundError: No module named 'loguru'`。
   - 现在脚本全部为纯 ASCII + CRLF 换行，并直接调用 `venv\Scripts\python.exe`，
     不再依赖 `activate.bat`，也不受代码页影响。
   - 新增：启动前检查环境与端口、等服务真正返回 200 后再打开浏览器、
     失败时给出可操作的提示而不是窗口一闪而过。
2. **`venv\Scripts\activate.bat`**：`VIRTUAL_ENV` 原本硬编码为旧目录
   `C:\Users\26733\Documents\Codex\AI4S-Discovery\venv`（项目被移动后仍在生效），
   已改为相对本文件的路径。
3. **arXiv 检索修复（`src/agents/search_agent.py`）**：arXiv 的 Atom 响应带命名空间，
   而解析代码按无命名空间查找子元素，导致每条记录除了空壳什么都没有——
   表现为"arXiv 50 篇"但去重后 0 篇、报告空白。现已按命名空间解析，
   并丢弃解析失败的空壳条目。
4. **`venv` 里的 pip 损坏**（缺 `pip/_internal/models`）已用 `ensurepip` 重建；
   原文件备份在 `.tmp\broken_pip_backup`。
5. **中文查询检索不到文献（2026-10-16 修复）**：arXiv / PubMed / Semantic Scholar
   都是英文库，直接搜中文必然 0 篇、报告为空；且 Semantic Scholar 未配 key 时
   会反复限流重试，造成"卡在检索"。现在中文查询会自动翻译成英文再检索，
   三个数据源改为并行搜索，限流重试也大幅缩短。
6. **结果页 HTTP 500 / 分析崩溃（2026-10-16 修复）**：
   - Semantic Scholar 会返回 `abstract: null` 的文献，分析环节对空摘要做切片会抛
     `'NoneType' object is not subscriptable`，导致分析整段失败；现已容错。
   - TRL 趋势拟合在退化数据上会算出 `NaN`，而网页返回 JSON 不允许 NaN，
     于是"查看结果"直接 500；现已兜底（趋势计算 + 接口双层防护）。
   - 另外中文长句需求（"……，需跨域文献支撑"）会整句翻译成英文，命中率很低；
     现在只取第一个小句作为检索主题（例："探索阿尔茨海默病免疫代谢靶点，需跨域文献支撑"
     → "Immunometabolic Targets in Alzheimer's Disease"，文献数从 5 篇提升到 78 篇）。
